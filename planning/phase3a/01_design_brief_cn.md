# SYDNEY'S WORLD｜第三阶段视觉改版 · 方案 A

> **只做设计规划、文案和工程规范，不直接替换当前线上页面。** 新图和资产处理属于后续方案 B。

## 1. 目标与定位

- 使用场景：小红书 REDesign 等创意／多媒体设计岗位的面试作品集。
- 定位：**一个具有明确视觉身份的互动作品集**，同时让面试官在 30 秒内找到真实项目与技术能力。
- 美术语言：来自本人《The Making of Pets》的虚构乌托邦／生态女性主义视觉实验：粉雾紫、珠光、奶油白、浅水绿；蜿蜒花叶、飞行动物、透明水体、珍珠、蕾丝和精致的 3D 渲染质感。
- 参考思想：House of Gül 的艺术性／装饰层次；haoqi.design 的信息层级与阅读清晰度。**不要直接复制任何参考网站的代码、图形和布局**。
- 核心概念：**Sydney's World / 灵感小岛**——一座由创意实验组成的虚构岛屿。景观是个人作品集的容器，而不是把《制作宠物》直接改名为网站。

## 2. 首页结构

1. `Header`：SYDNEY'S WORLD 字标／作品／关于／联系。可加小号英文 WORK / ABOUT / CONTACT，但中文操作文字必须清晰。
2. `Hero`：一座珠光白、淡粉紫的漂浮岛，带泉水、花卉、空中动物和轻量展台；首屏写 `SYDNEY'S WORLD`，副标题为 `欢迎来到我的灵感小岛。`，并有 `查看全部作品`。
3. `Hero hotspots`：在岛屿 5 个具有物理空间意义的位置添加统一视觉标记（如插牌、门、光圈、迷你展台）。标记对应核心作品。点击弹出中文预览卡，再进项目详情。不要把项目真实图片直接摆成五张乱飞的贴纸。
4. `Selected Works`：保持清楚的作品入口，按用户优先级展示 8 个主作品；Horse Motion Study 作为与 Stubborn Horse 分开的独立实验，可在 Creative Coding 分类与精选项目关联入口展示。
5. `About`：中文求职介绍 + 核心技术能力分组，清晰体现视觉设计、动效与 3D、创意编程、物理计算、Vibe Coding。
6. `Contact`：真实邮箱、GitHub、Instagram，取消 coming soon。

## 3. Hero 2.5D 图层策略

- B0：天空与远景，WebP，**没有文字、没有按钮**。
- B1：岛屿主体，透明 WebP/PNG，带中央喷泉及统一的地面／透视／投影。
- B2：岛屿表面局部植物与建筑小景，透明图；推荐拆成 2–3 层。
- F1：前景枝叶、飞行动物，最多 3–5 个可独立轻微漂移的装饰层。
- UI：DOM 中真实按钮/热点，中文 hover/focus 提示，绝不把交互标签烘焙到背景图里。
- Parallax.js 控制包裹层位置；内层 CSS 控制 hover/focus，避免冲突。最多 3 档景深，交互幅度克制。
- 手机端改为一张裁切安全的场景插画 + 可读作品入口；不强制桌面同构图。

## 4. UI / Typography

- 主标题文字优先用真实 HTML 文本与 CSS 设计；如要定制 logo lettering，可额外提供 SVG/装饰层，**不要把全部正文烘焙进图片**。
- 中文可读性优先：建议无衬线正文，搭配适量装饰性西文字体（授权与网络字体加载需检查）。
- 色彩：珠光奶油白 `#F7F3F1`、浅粉 `#F4DCE8`、薄雾紫 `#DCCCF2`、浅水绿 `#D3E7DC`、深紫灰文字 `#302938`。明确焦点色与足够的对比度。页面不必全部涂粉。
- Ornament 只在 Hero、页脚、视频大图边缘点到为止；详情页主要让作品照片和视频发声。
- 常用交互文案：`探索小岛` `查看全部作品` `了解项目` `播放影片` `在线体验` `查看代码` `返回作品` `继续探索` `点击岛上标记进入作品`。

## 5. 项目详情页（求职阅读优先）

首屏：分类 + 中文项目名 + 英文原题 + 50 字内一句话；大幅 Hero 图。下一屏：`设计概念`、`我的工作`（团队项目需要核实分工）、`技术与工具`；随后是**有节奏的图库**（大图/并排/竖版可变，而不是同一网格强制所有项目相同），最后是 `影片` 和 `在线体验 / 查看代码`。每页底部 `下一件作品`。

**视频设计**：每条视频都有本地大图封面（优先来自真实作品画面），封面中央带 Play 按钮，点击才装载视频；YouTube 用 `youtube-nocookie.com/embed/{id}` 或打开新窗口作为完整影片方案，公开网站必须提供外链 fallback。在中国大陆面试浏览时 YouTube 可能无法播放，因此对重点项目建议另备压缩的本地 H.264 MP4（短版）或可访问的国内平台链接。不要将 YouTube 远程缩略图作为唯一封面，也不要加载一屏黑色播放器占位。

**体验按钮**：`在线体验` 是最明显 CTA；`观看影片` 次级；`查看代码` 可作为轻量链接。如果项目没有 demo/github，就不要渲染空按钮。对需要摄像头的 Oracle 给出 `需要允许摄像头权限` 提示。对 Onrender 冷启动可用友好提示，不虚构保证性时间。

- 所有未确认年份保持空；删除现有网站低清图片、临时封面、coming soon 等开发备注（可留内部资产 TODO）。
- 不将新生成的装饰图谎称为原始项目成果；新图用于站点包装，原作品展示保留真图。

## 7. 性能与工程

- 沿用已经部署的 **Vite + 原生 JS + Parallax.js + GitHub Pages**，保留 `./` base 与 hash 路由。
- 文件分类：`public/assets/world/` 场景；`public/assets/ui/` 图标／装饰；`public/assets/posters/` 视频海报；`public/assets/projects/{slug}/` 真实项目。
- 指定海报原则：横版 1600×900 WebP（约 150–400KB，视画质调整）；物件最长边 800–1200px，透明 WebP 优先；背景最长宽 1920–2400px，响应式输出更小版本。保留源文件单独归档，不把 252MB 的 sucai.zip 或 465MB 的 png.zip 原包提交站点。
- 不是所有视觉裁成 16:9：城市竖版海报、Chroma 竖图应保持原始比例，布局用 CSS 保持完整展示。
- 视频懒加载，仅点击才请求，进入其他页面停播；移动端关注页面首屏载入和交互可达性。
- 修改在新分支，构建与 Playwright 测试通过后经 PR 合并；不要直接覆盖稳定线上站点。
